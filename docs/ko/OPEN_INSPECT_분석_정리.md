# Open-Inspect (background-agents) 분석 정리

이 문서는 저장소 전수조사 후 나눈 대화(질문 1~4)를 정리한 것입니다.

- 이 저장소(포크): https://github.com/bmshin94/background-agents
- 원본 저장소(업스트림): https://github.com/ColeMurray/background-agents
- 영감을 준 원문(Ramp Inspect): https://builders.ramp.com/post/why-we-built-our-background-agent
- 라이선스: MIT (상업적 사용·수정·재배포 가능, 저작권 고지 유지 필요)

---

## 1. 이게 뭐하는 건지 (전수조사 결과)

### 한 줄 요약

**"클라우드에 떠 있는 AI 개발자"를 우리 회사(나) 전용으로 직접 설치해서 운영하는 오픈소스 시스템.**
미국 핀테크 회사 Ramp가 사내에서 쓰는 "Inspect"(Ramp PR의 약 30%를 작성)를 누구나 따라 만들 수 있게
공개한 구현체입니다.

### 무엇을 하나

1. 웹 / Slack / GitHub PR 댓글 / Linear 이슈 / Webhook 으로 "이 버그 고쳐줘" 같은 요청을 보냄
2. 클라우드에 **격리된 개발용 컴퓨터(샌드박스)** 가 즉시 켜짐 (Node 22, Python 3.12, git, 브라우저,
   VS Code 포함)
3. 그 안에서 AI 코딩 에이전트(OpenCode 또는 Claude Agent SDK)가 코드 수정 → 테스트 → 브라우저
   스크린샷 검증
4. 결과를 **Pull Request** 로 올리고, 진행 상황을 실시간 스트리밍
5. 내 노트북은 꺼도 됨 (그래서 "백그라운드" 에이전트)

### 구조 (3계층)

| 계층          | 기술                                                           | 역할                                                    |
| ------------- | -------------------------------------------------------------- | ------------------------------------------------------- |
| 웹 클라이언트 | Next.js 16 + React 19                                          | 로그인, 세션 목록, 실시간 채팅/로그 화면                |
| 컨트롤 플레인 | Cloudflare Workers + Durable Objects + D1 (또는 Node 컨테이너) | 세션 관리, WebSocket 허브, GitHub 연동, 암호화된 시크릿 |
| 데이터 플레인 | Modal / Daytona / E2B / Vercel Sandbox / OpenComputer          | 샌드박스 생성·스냅샷·이미지 빌드                        |
| 봇            | Cloudflare Workers + Hono                                      | slack-bot, github-bot, linear-bot                       |

### 주요 기능

- **빠른 시작**: 파일시스템 스냅샷, 30분마다 미리 빌드되는 이미지, 타이핑 시작하면 미리 샌드박스
  예열
- **멀티 레포 세션**: 한 세션에서 최대 10개 저장소 동시 수정, 저장소별 PR
- **멀티플레이어**: 여러 명이 한 세션에 같이 접속, 커밋은 프롬프트 작성자 이름으로
- **자동화**: 크론 스케줄, Sentry 알림, GitHub Actions 결과, Webhook 트리거 → 사람 없이 자동 작업
- **자식 세션**: 에이전트가 일을 쪼개서 병렬 샌드박스에 나눠 맡김
- **Managed Skills**: 팀 공용 작업 지침(SKILL.md)을 저장소별로 자동 주입
- **멀티 모델**: Claude(API 키 또는 Claude 구독), OpenAI(ChatGPT 구독), Grok, OpenCode Zen/Go 등
- **보안**: 시크릿 AES-256-GCM 암호화, 짧은 수명의 GitHub App 토큰 중개, 워크스페이스 역할/감사 로그

### 언제 쓰나

- 자잘한 버그·리팩터링·의존성 업데이트를 "던져두고" 다른 일을 하고 싶을 때
- 같은 작업을 여러 모델/방식으로 동시에 시도해 보고 좋은 PR만 고르고 싶을 때
- 밤에 떠오른 아이디어를 폰(Slack)으로 던지고 아침에 PR로 받고 싶을 때
- Sentry 에러가 뜨면 자동으로 원인 분석·수정 PR까지 받고 싶을 때
- 비개발자(기획/디자인)도 개발 환경 없이 간단한 수정 요청을 하게 하고 싶을 때

### 나한테 무슨 도움이 되나

- **생산성**: 동시에 여러 작업을 AI에게 병렬로 맡기는 "AI 팀원" 확보
- **학습 교재**: Cloudflare Durable Objects, WebSocket 스트리밍, 샌드박스 오케스트레이션, OAuth,
  Terraform, RBAC 등 실서비스급 설계를 통째로 볼 수 있는 교과서
- **사업 기반**: MIT 라이선스라 그대로 커스터마이징해서 서비스/설치대행 가능

### 주의점

- **싱글 테넌트 전용**: 한 조직 안의 믿을 수 있는 사람들끼리 쓰는 구조. 여러 회사가 같이 쓰는 SaaS로
  바로 팔면 안 됨(테넌트 격리 추가 개발 필요)
- 설치 난이도가 높음(여러 클라우드 계정 + Terraform, 1~3시간 이상)
- 사용량만큼 클라우드·LLM 비용 발생

## 2. 더 쉽게 설명

비유하자면 **"AI 알바생 사무실"** 입니다.

| 실제 구성요소          | 비유                                                          |
| ---------------------- | ------------------------------------------------------------- |
| 웹 / Slack / GitHub    | 알바생에게 일을 시키는 **카톡방·접수창구**                    |
| 컨트롤 플레인          | 일을 받아 배정하고 진행 상황을 알려주는 **매니저**            |
| 샌드박스               | 알바생마다 하나씩 주는 **깨끗한 개인 책상 + 컴퓨터**          |
| AI 에이전트(Claude 등) | 실제로 코드를 고치는 **알바생**                               |
| Pull Request           | 알바생이 제출하는 **결과 보고서** — 사장님(나)이 검토 후 승인 |
| 스냅샷/프리빌드 이미지 | 책상을 미리 세팅해 둬서 **출근하자마자 바로 일 시작**         |
| 자동화                 | "매일 아침 9시에 이거 해놔" 같은 **정기 업무 지시**           |
| 자식 세션              | 알바생이 일이 많으면 **다른 알바생을 불러서 나눠서 처리**     |

흐름: 카톡으로 "로그인 버튼 색 바꿔줘" → 매니저가 새 책상 배정 → 알바생이 코드 고치고 화면 캡처로
확인 → PR 제출 → 나는 확인 버튼만 누르면 끝.

## 3. 자주 묻는 질문

### 3-1. 설치 및 사용법

세 가지 경로가 있습니다 (`docs/SETUP_GUIDE.md`).

| 경로   | 목적                                  | 소요 시간 |
| ------ | ------------------------------------- | --------- |
| Path A | 이미 배포된 백엔드에 로컬 웹만 붙이기 | 10~20분   |
| Path B | 코드 기여용 로컬 개발(린트/테스트)    | 15~30분   |
| Path C | 내 전용 풀스택 배포                   | 1~3시간   |

**풀 배포(Path C) 요약** — `docs/GETTING_STARTED.md`

1. 계정 준비: Cloudflare, (Vercel 또는 Cloudflare로 웹), 샌드박스 제공자(Modal 기본), GitHub,
   Anthropic(또는 다른 모델 구독), 선택으로 Slack/Linear
2. 도구 설치: Terraform 1.14+, Node 22+, Python 3.12 + uv, Wrangler
3. 저장소 포크·클론 후 `npm install`
4. GitHub App 생성(OAuth + 저장소 권한), PKCS#8 키 변환
5. `terraform.tfvars` 한 파일에 값 채우기 → `terraform apply` (Durable Object 바인딩은 2단계 배포)
6. Modal 이미지 빌드·배포
7. 웹에 GitHub로 로그인 → 저장소 선택 → 프롬프트 입력

**Docker 방식**(Cloudflare 없이 컨트롤 플레인 실행): `cp .env.example .env` → 값 채우기 →
`docker compose up --build`. 웹은 `next dev`로 따로 실행. 단, 샌드박스는 여전히 Modal 등 클라우드
제공자가 필요.

**Claude Code로 설치 도움받기**: 저장소에 포함된 `onboarding` 스킬을 실행하면 단계별로 안내.

**사용법**: 웹에서 저장소·모델·하네스 선택 → 프롬프트 입력 → 실시간 로그/터미널/VS Code로 확인 → PR
생성. Slack에서 @멘션, GitHub PR 댓글 @멘션, Linear 이슈 할당으로도 시작 가능.

### 3-2. 플러그인? 스킬? MCP?

**셋 다 아닙니다. 독립 실행형 "풀스택 애플리케이션(플랫폼)"** 입니다.

- 플러그인/스킬/MCP는 Claude Code 같은 도구에 "끼워 넣는 부품"
- Open-Inspect는 그런 AI 도구를 클라우드에서 대신 돌려주는 **서버 시스템 전체**
- 다만 내부에서 **스킬(Managed Skills)** 과 **MCP 서버 연결**을 지원하고, 저장소 안에 설치 도우미용
  Claude Code 스킬(`.claude/skills/onboarding`)이 하나 들어 있음

### 3-3. API 토큰이 필요한가?

**네, 여러 개 필요합니다.**

| 종류                           | 필수 여부          | 비고                                                                                              |
| ------------------------------ | ------------------ | ------------------------------------------------------------------------------------------------- |
| AI 모델 인증                   | 필수(택1+)         | `ANTHROPIC_API_KEY`, 또는 Claude 구독 연결(Claude Agent 하네스), ChatGPT 구독 OAuth, SuperGrok 등 |
| GitHub App (ID, 개인키, OAuth) | 필수               | 클론/푸시/PR 생성                                                                                 |
| Cloudflare API 토큰            | Cloudflare 배포 시 | Workers, D1, KV, R2                                                                               |
| 샌드박스 제공자 토큰           | 필수(택1)          | Modal `MODAL_TOKEN_ID/SECRET`, 또는 Daytona/E2B/Vercel/OpenComputer 키                            |
| Vercel 토큰                    | 선택               | 웹을 Vercel에 올릴 때만                                                                           |
| Slack/Linear 토큰              | 선택               | 봇 연동 시                                                                                        |
| 암호화 키 3종                  | 필수               | `openssl rand -base64 32`로 직접 생성                                                             |

### 3-4. 왜 GitHub에서 유명한가

1. **Ramp의 화제성**: "PR의 30%를 AI가 쓴다"는 Ramp 블로그 글이 크게 화제가 됐고, 그 설계를 실제로
   동작하는 오픈소스로 구현
2. **"백그라운드 에이전트"라는 트렌드**: 로컬 IDE 보조 → 클라우드에서 혼자 일하는 에이전트로
   넘어가는 흐름의 대표 구현체
3. **자체 호스팅(Self-hosted)**: 코드·시크릿을 외부 SaaS에 안 맡기고 우리 인프라에서 운영 가능
4. **모델 종속 없음**: Claude, GPT, Grok, 오픈 모델 등 선택 가능, 기존 구독 재활용
5. **실무 완성도**: 스냅샷, 멀티플레이어, 자동화, RBAC, 감사로그, Terraform까지 제품 수준
6. **MIT 라이선스** + 활발한 업데이트(CHANGELOG 기준 매주 기능 추가)

### 3-5. 로컬 에이전트 구축에 도움이 되나

**설계 교과서로는 매우 큰 도움, 그대로 "완전 로컬"로 쓰기에는 한계.**

- 도움 되는 부분: 세션 상태 관리, WebSocket 이벤트 스트리밍, 에이전트 하네스 추상화
  (`packages/sandbox-runtime/src/sandbox_runtime/harness/` — OpenCode·Claude), 샌드박스 수명주기,
  git 자격증명 중개, 스냅샷, 스킬 주입, 자식 세션 설계
- 한계: 샌드박스가 Modal·E2B 같은 **클라우드 제공자 전제**이며 로컬 Docker 샌드박스 제공자는 없음.
  컨트롤 플레인은 Docker로 로컬 실행 가능(`docker-compose.yml`)
- 추천: 이 구조를 참고해서 "로컬 Docker 컨테이너 = 샌드박스"로 바꾼 미니 버전을 직접 만들거나,
  샌드박스 제공자 인터페이스에 로컬 Docker 제공자를 추가하는 방식

### 3-6. 수익화 아이디어

4장에서 자세히 정리.

### 3-7. React나 PHP로 만들 수 있나

- **React**: 이미 웹 UI가 Next.js(React 19)라서 **바로 커스터마이징 가능**. 화면·브랜딩
  (`NEXT_PUBLIC_APP_NAME` 등) 수정은 쉬움
- **PHP**: 전체를 PHP로 재작성하는 건 비추천. 장시간 WebSocket, Durable Objects, 샌드박스 SDK(주로
  Python/TS), Claude Agent SDK(TS/Python) 때문에 궁합이 안 좋음
- **현실적인 미니 버전 구성 예시**
  - 프론트: React (Vite 또는 Next.js)
  - 백엔드/관리: PHP(Laravel) 가능 — 작업 접수, 사용자·과금, 큐 관리
  - 실시간: Laravel Reverb 또는 Node WebSocket 서버
  - 워커: Node/Python에서 Claude Agent SDK 또는 `claude` CLI 실행
  - 샌드박스: 작업마다 Docker 컨테이너 생성 → 저장소 클론 → 에이전트 실행 → PR 생성
  - 핵심 기능만(요청 → 샌드박스 → PR) 구현하면 MVP 규모는 충분히 도전 가능

## 4. 수익화 아이디어 상세

> 금액은 이해를 돕기 위한 예시이며 시장 조사 후 조정 필요. MIT 라이선스라 상업 이용 가능하지만
> 저작권 고지는 유지해야 합니다.

### 비용 구조 먼저 이해하기

- Cloudflare Workers 유료 플랜(월 소액) + Modal 등 샌드박스 사용 시간 과금 + LLM 토큰 비용
- 즉 **작업 1건당 원가**가 존재 → 가격은 "원가 + 설치/운영 가치"로 설계

### 아이디어 1. 설치·운영 대행 (가장 현실적, 바로 시작 가능)

- 대상: 개발팀 5~50명 규모 스타트업·중소기업
- 내용: 고객사 클라우드 계정에 Open-Inspect 설치(싱글 테넌트라 고객사별 설치가 오히려 정석),
  GitHub/Slack 연동, 사내 규칙 스킬 세팅, 유지보수
- 수익 모델: 설치비(1회) + 월 운영·업데이트 관리비
- 장점: 원본 구조 그대로 활용, 보안 모델과 충돌 없음

### 아이디어 2. 한국형 메신저 연동판

- slack-bot 구조를 본떠 **카카오워크 / 잔디 / 네이버웍스 / 디스코드 봇** 추가
- 한국어 UI·문서 번역 + 국내 결제
- 수익 모델: 연동 모듈 판매 또는 설치 패키지에 포함해 단가 상승

### 아이디어 3. 에이전시형 "AI 유지보수 월정액"

- React·PHP 웹 에이전시라면 고객사 유지보수 요청(문구 수정, 버그, 간단 기능)을 에이전트가 PR로 처리
- 사람은 검토·배포만 담당 → 같은 인력으로 더 많은 고객 유지보수 가능
- 수익 모델: 고객사당 월정액, 요청 건수 구간별 요금제

### 아이디어 4. 스킬·자동화 템플릿 팩 판매

- Managed Skills(SKILL.md)와 자동화 레시피를 업종·스택별로 패키지화
  - 예: "Laravel 보안 점검 팩", "React 접근성 자동 개선 팩", "Sentry 에러 자동 트리아지 팩", "주간
    의존성 업데이트 팩"
- 수익 모델: 팩 단위 판매, 구독형 업데이트

### 아이디어 5. 고객 요청 → PR 자동화 포털

- 비개발자 고객이 폼/Webhook으로 수정 요청 → 에이전트가 PR + 미리보기 URL(포트 터널) + 스크린샷 생성
  → 담당자 승인 후 배포
- 수익 모델: 포털 구축비 + 건당/월 과금

### 아이디어 6. 교육·컨설팅 콘텐츠

- "사내 AI 백그라운드 에이전트 구축" 강의, 기업 워크숍, 기술 블로그·유튜브
- 이 저장소가 실서비스급 아키텍처 교재 역할
- 수익 모델: 강의 판매, 기업 교육비, 컨설팅

### 아이디어 7. 멀티 테넌트 SaaS (난이도 최상, 장기 목표)

- 여러 회사가 가입해서 쓰는 서비스로 전환
- 필요 작업: 테넌트별 GitHub App 설치, 세션 생성 시 접근 검증, 데이터 모델 테넌트 격리, 과금·사용량
  계측 (README의 "For multi-tenant deployment" 항목)
- 수익 모델: 좌석당 월 구독 + 사용량 과금

### 추천 순서

1. 우리 팀에 먼저 설치해서 직접 써보기 (포트폴리오·사례 확보)
2. 아이디어 1·3으로 소규모 매출 시작
3. 운영하며 쌓인 노하우를 아이디어 4·6으로 상품화
4. 수요가 확인되면 아이디어 2·5·7로 확장
